## Design Specificity Verdict

The charcoal felt, parchment headings, phase rail, stack, card art, and priority-aware action panel are authored for a tabletop network match rather than a generic desktop app. The principal gap is not visual identity but decision support: the UI exposes enough server truth to understand the board, but not enough guidance or recovery to act confidently under priority.

Native Tkinter has no browser surface for the Impeccable CLI detector or visual overlay. A source/test inspection found 0 P0, 2 P1, 5 P2, and 2 P3 issues. The live-window smoke tests could not run because the installed Python lacks Tcl/Tk.

## What's Working

- The spatial model is strong: phases left, battlefields/stack/hand centered, actions/history right.
- Server authority is legible through phase, priority, state synchronization, and contextual legal actions.
- Card images, cached at first use, and action filtering offer a practical foundation for a demonstration-friendly client.

## Priority Issues

### [P1] No recovery route after an in-game disconnect

`client/gui.py:224-232` changes the status/log but leaves the action screen attached to a failed transport after `attach_session`. Close and clear the failed session, disable game controls, and provide Reconnect / Return to connection form while preserving connection details and deck choice.

### [P1] High-stakes interaction is weakly discoverable and keyboard-poor

`client/gui.py:435-447` makes image cards blank-text click targets and hides inspection behind double-click. `client/gui.py:700-786` has incomplete keyboard modal behavior. Add explicit select/inspect affordance, named focusable cards, visible focus, keyboard card navigation, Enter/Escape conventions, and a documented pass-priority accelerator.

### [P1] Blocker assignment silently defaults every blocker to attacker one

`client/gui.py:759-783` preselects the first attacker. Use a required “Choose attacker” placeholder, block confirmation until each assignment is intentional, and summarize the final blocking map before sending.

### [P2] Layout will clip on compact or high-DPI desktop windows

`client/gui.py:84-86` fixes a 1080x720 minimum while `:247-337` has a fixed sidebar and no whole-window scrolling or reflow. Add a compact layout mode: collapsible/grouped phase rail, vertically scrollable game surface, and a docked/bottom action panel at narrow widths.

### [P2] Full widget recreation on every update loses focus and can stall

`client/gui.py:415-485` destroys/rebuilds all zones per update; selection rerenders three zones at `:503-515`. Reconcile tiles in place or coalesce updates, retain focus, bound event-bridge work per tick, and cap activity-log history.

### [P2] Decision feedback uses implementation IDs and raw protocol errors

`client/gui.py:508` lists IDs such as `lightning_bolt_003`; `:834-837` surfaces server code/message. Use readable names plus tactical state (“Selected: Lightning Bolt - choose a target”), retain diagnostic codes only in Activity, and map expected rejections to a next-step instruction.

## Persona Red Flags

- **First-time player:** no in-app explanation that card selection drives right-panel actions, no visible cue for double-click inspection, and legal-target prompts explain little about why targets are available.
- **Experienced player:** no predictable keyboard shortcut for pass priority, no keyboard reordering, and repeated pointer/card reselection during turn loops.
- **Keyboard/accessibility user:** image-only buttons lack text when images load; selection/phase/tapped state are partly color-only; full rerenders can drop focus.

## Minor Observations

- Add a Close button and Escape behavior to card detail windows.
- Give Activity a scrollbar and finite history.
- Replace the generic “State synchronized with the server” footer with the specific result of the last accepted action.

## Questions to Consider

- Should the phase rail serve evaluator completeness or player decision support? The best density differs.
- Can the client safely offer a non-authoritative tactical preview (for example, “these are legal targets”) without implying it decides rules?
